# SB-XIDのPI目的関数の範囲限定と比較

`exp/sb-xid` の `0c9c3ac` を基点に、CaDiCaLの正常CNFの範囲外にあるPIをSB-XIDの目的関数から外した。
範囲外PIは返却キューブでXにする。範囲内PIだけを対象とする `scope` を既定にし、
従来の `all` も比較用に選べる。全PIの数・順序とFDPの分母は変えない。

## 実装

対象故障のTFOに含まれるPOを選び、その全TFIをたどった範囲を使う。
故障のTFOとPOのTFIの共通部分だけにするとサイド入力を落としてしまうため、正常側の範囲は対象POの**全TFI**とする。
本体がすでに `NormalScopeBuild()` で求めた結果を利用する。

`WriteTPGModel()` の後で `NormalScopeRequiredNet(pi[p]->n)` をPI順のマスクへ保存し、
`sbxid_generalize()` へ渡す。workerごとに配列を持ち、故障が変わると更新する。
禁止節に登場したPIも含む `NormalScopeRequiredPi()` は目的関数には使わない。

比較する目的関数の差は、範囲外PIの正のケア費用だけである。
PI変数の割当て、制約式、PIの主目的重み、正常・故障の内部ケア費用、1秒の探索上限はそろえた。
シミュレーション範囲やPATH/JUSTIFYは追加削減しない。

範囲外PIは制約から独立しているため、全PI版の最適解ではそのケア変数を0にできる。
その項を外しても、範囲内の最小ケアPI数と内部費用の最適値は変わらない。
ただし、費用のなくなったPI変数がモデル上で1になることは許されるので、キューブ抽出時に明示的にXへ正規化する。
最適性が未証明の暫定解にも同じ処理を適用する。

解なしUNKNOWNと任意の事後検証の失敗では、従来どおり元の全PIの2値seedへ戻す。
マスクがSBのPATH/JUSTIFYに必要なPIを欠く場合は求解前にエラーとする。

## 条件

2026-10-22、Linux、GCC 14.2.0、clasp 3.3.9、CPUクォータ2コア相当。
両方式で3値事後検証を有効にした。同じ通常Releaseコードのオプションを切り替えて比較した。
詳細データは [確認記録](sb_xid_pi_objective_checks.json) に保存した。

### 同じ故障・seedの全4,511組

`SB-XID/tp/1f1p/` のs5378_C参照故障と検出パターンを全件使用。
参照PI順を本体のPI順へ変換し、1 worker・clasp探索1スレッドで実行した。
実行順は `all → scope → scope → all → all → scope`。

目的関数のPI項は、全PI版の214個に対し、範囲内PI版は中央値24個、平均35.94個、最小1個、最大141個だった。
同じ故障・seedでは、両方式のOPB変数数・制約数は全件同じだった。

| 測定 | 全PI | 範囲内PI |
|---|---:|---:|
| SB呼出し時間・1回目 | 69.809秒 | 67.237秒 |
| SB呼出し時間・2回目 | 67.270秒 | 59.992秒 |
| SB呼出し時間・3回目 | 84.359秒 | 66.186秒 |
| SB呼出し時間の中央値 | **69.809秒** | **66.186秒** |
| clasp探索時間の中央値 | 61.290秒 | 58.061秒 |
| 平均確定PI数・各測定の中央値 | 7.90024 | 7.89980 |
| 時間切れ件数・3回合計 | 20 | 13 |
| 解なしUNKNOWN・3回合計 | 0 | 0 |

SB呼出し時間の中央値は約**5.2%短縮**。
この時間にはOPB生成、clasp読込・前処理・探索、キューブ抽出、3値事後検証を含む。
回路読込、正常CNFの範囲抽出、CSV書込は含まない。実行間のばらつきは表のとおりである。

両方式で最適解だった組は、3回合計13,509比較で確定PI数がすべて一致した。
時間切れの暫定解を含めた平均品質の差は小さい。
キューブ自体は各測定で170～173組異なり、同じ最小ケア数でも別の解を選ぶ場合がある。
返却キューブの3値故障検出チェックは全件成功した。

### 本体の200故障・30キューブ上限

参照故障4,511行から `floor(k*4510/199), k=0..199` で200故障を選び、
本体のCaDiCaLによるseed生成・SB-XID・禁止節・BDDを実行した。
同じ200故障を使い、2 worker、流用off、30キューブ上限、各方式1回、順番は `all → scope`。
3値事後検証に加え、CaDiCaLの正常SAT値とseedシミュレーション値の照合も有効にした。

| 測定 | 全PI | 範囲内PI |
|---|---:|---:|
| 本体経過時間 | **64.007秒** | **59.165秒** |
| CPU時間 | 121.461秒 | 113.591秒 |
| SB-XID CPU時間 | 119.098秒 | 111.079秒 |
| SB-XID呼出し回数 | 4,209 | 4,209 |
| clasp時間切れ件数 | 29 | 19 |
| 解なしUNKNOWN | 0 | 0 |
| 完全列挙できた故障 | 80 | 80 |
| 上限で未完了の故障 | 120 | 120 |
| 3値事後検証の失敗 | 0 | 0 |

この200故障での本体経過時間は約**7.6%短縮**。
完全列挙できた故障集合は一致し、その80件のFDPもすべて一致した。
未完了120件のFDP下界は、範囲内PI版が高いもの18件、全PI版が高いもの13件、同じもの89件だった。
同点解や途中のseedが変わるため、30キューブ上限での被覆は全故障で一方向には改善しない。

s5378の全4,551代表故障を両方式で完走する比較は行っていない。
固定seed全件の結果と、本体200故障の結果を区別して読む。

## 正しさの確認と再現

9件のCTestがすべて成功した。
新しい単体テストでは、別の外部出力を持つ無関係なPIを含む小回路についてPBOモデルを全列挙し、
制約本文と最適費用の一致、範囲外PIのモデル値1をXへ戻す処理、暫定解・UNKNOWN・不正マスクを確認する。

実claspでの統合テストでは、c17a・s27_Cの無制限キューブ列挙をDebug/Release、全PI/範囲内PI、1/2 workerで比較し、完全FDPが一致した。
c17aは既知の期待値とも一致した。CLI・`.set`・既定値・CLI上書きも確認した。

切替は `-sbxid_pi_objective all|scope`。省略時は `scope`。
通常のビルド・テストに加え、比較は以下で再現できる。リポジトリルートで実行する。

```bash
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
cmake --build build --target sbxid_pi_objective_benchmark --parallel 2

python3 tests/sbxid_pi_objective_compare.py \
  --binary build/sbxid_pi_objective_benchmark \
  --output output/sbxid/pi-objective-comparison --samples 4511 --trials 3

python3 tests/sbxid_pi_objective_application_compare.py \
  --binary build/main_release --jobs 2 --fault-samples 200 \
  --output output/sbxid/pi-objective-application-sample200
```

`--fault-samples` を省略すると本体が生成する全代表故障が対象になる。
各出力ディレクトリにCSV、ログ、集計JSONを保存する。
