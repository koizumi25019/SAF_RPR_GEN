SB-XID 使い方（補足）
================================================================
このファイルは「exe用のフォルダ\saxid_v1_使い方.txt」に書かれていない点をまとめたもの。
コマンドラインの書き方・オプション・結果ファイルの列・bat の使い方は
「exe用のフォルダ\saxid_v1_使い方.txt」を見ること（ここでは繰り返さない）。

----------------------------------------------------------------
1. どこで実行するか
----------------------------------------------------------------
  実行の方法は次の2つ。

  (A) exe用のフォルダ\saxid_v1.exe を使う（おすすめ）
      必要なもの（回路・パターン・clasp.exe・bat）がそろっている。
      コマンドプロンプトでは、まず次のようにこのフォルダへ移動する。
        cd /d C:\Users\kusag\Desktop\SB-XID\exe用のフォルダ
      ※ saxid_v1_使い方.txt の例にある
         「cd /d C:\Users\owner\source\repos\hosonas\saxid_v1」は別のPCのパス。
         このPCでは上のパスに読みかえる。

  (B) このフォルダ（SB-XID）でソースからビルドした exe を使う
      SB-XID.sln を Visual Studio 2022（ツールセット v143）で開き、x64 でビルドする。
      Debug|x64 なら x64\Debug\SB-XID.exe ができる。
      saxid_v1.exe と同じプログラムで、ファイル名だけが違う。
      このフォルダで、例えば次のように実行する。
        cd /d C:\Users\kusag\Desktop\SB-XID
        x64\Debug\SB-XID.exe circuit\s5378_C.v tp\mfmp\s5378_C_tp_fault.txt tp\mfmp\s5378_C_tp.txt s5378_result.txt s5378_xtp.txt --batch --threads=16
      Visual Studio から実行（F5）するときの引数は、プロジェクトのプロパティ
      →「デバッグ」→「コマンド引数」で設定する（今は s5378 / tp\mfmp の例が入っている）。

  どちらの場合も、clasp.exe がある「今いるフォルダ」で実行すること。
  プログラムは .\clasp.exe を呼ぶため、別のフォルダから実行すると
  すべての行が ERROR(Clasp) になる。
  また、実行したフォルダに OPB_Files\、clasp_out.txt が作られる。

----------------------------------------------------------------
2. このフォルダ（SB-XID）の構成
----------------------------------------------------------------
  SB-XID.sln / SB-XID.vcxproj  Visual Studio のプロジェクト
  src\saxid.c                  本体（X 判定・OPB 生成・clasp 呼び出し・検証）
  src\Netlist.c, Netlist.h     回路(.v)の読み込み
  clasp.exe                    ソルバー（exe用のフォルダ\clasp.exe と同じもの）
  circuit\                     回路（exe用のフォルダ\circuit\ と同じもの）
  tp\mfmp\                     通常の STTG パターン（= exe用のフォルダ\tp\ と同じ内容）
  tp\1f1p\                     1故障1パターン（= exe用のフォルダ\tp_1f1p\ に対応）
  x64\Debug\SB-XID.exe         ビルドした exe
  exe用のフォルダ\             配布用一式（saxid_v1.exe と説明書）

  ※ フォルダ名がちがうので注意する。
       このフォルダ        exe用のフォルダ
       tp\mfmp\       ←→   tp\
       tp\1f1p\       ←→   tp_1f1p\

----------------------------------------------------------------
3. パターンファイルの書き方（詳しく）
----------------------------------------------------------------
  ・1行 = 1パターン。1文字が外部入力1本に対応する。
  ・文字の順番は、回路ファイル(.v)の「input」の行に書かれた信号線の順番。
      例: s27_C.v は「input G7, G6, G5, G3, G2, G1, G0;」なので、
          パターン「0100001」は G7=0, G6=1, G5=0, G3=0, G2=0, G1=0, G0=1。
    tp\...\pin_<回路>_C.txt は、この順番で入力名を1行に1つずつ並べたもの。
    （プログラムはこのファイルを読まない。順番の確認用）
  ・長さは回路の外部入力数と同じにする（s5378 なら 214 文字。pin_s5378_C.txt の行数と同じ）。
    短いとはみ出した部分が正しく読まれず、長いと余った文字は無視される。
  ・使える文字
      1         1
      0         0
      - X x     X（ドントケア）。入力パターンに最初から X があってもよい。
                このとき結果ファイルの Diff は「増えた X の数」になる。
    それ以外の文字はすべて 0 として扱われる（エラーにならないので注意）。
  ・回路の「_C」は、フリップフロップを外部入出力に置きかえた組合せ回路の意味。
    そのため入力数には、元の外部入力に加えてフリップフロップの数が含まれる。

----------------------------------------------------------------
4. 故障ファイルの書き方（故障名の決まり）
----------------------------------------------------------------
  1つの故障は「名前 sa0」「名前 sa1」で書く（書き方は saxid_v1_使い方.txt のとおり）。
  「名前」は次の決まりで付ける。回路に無い名前は ERROR(NoNet:名前) になる。

  (1) 分岐の無い信号線   → .v に書かれた信号線名そのまま
        例: n1334gat sa0
  (2) 分岐のある信号線（1本の信号線が2つ以上のゲートに入る）
      ・分岐の元（幹）     → 信号線名そのまま
      ・分岐の先（枝）     → <信号線名>_<入る先のゲートの出力信号線名>_<ピン名>
        例: G14_G8_A sa1  （G14 が、出力が G8 のゲートの A ピンに入る枝）
        ピン名は .v に書かれたピン名（A, B, C, D）。
  (3) 外部出力(output)でもあり、さらにゲートにも入る信号線
      ・分岐の元（幹）     → <信号線名>_stem
      ・外部出力へ行く枝   → 信号線名そのまま
      ・ゲートへ行く枝     → (2) と同じ
        例: s5378 の n2307gat（外部出力で、出力が n2663gat のゲートの C ピンにも入る）
              n2307gat_stem      幹
              n2307gat           外部出力へ行く枝
              n2307gat_n2663gat_C  ゲートへ行く枝
  ・tp\...\*_tp_fault.txt / *_1f1p_fault.txt にある名前は、この決まりで書かれている。
    新しく故障を指定するときは、これらのファイルの名前を参考にするとよい。

  ・空行は読み飛ばされる（パターンファイルの同じ行も一緒に飛ばされる）。
    故障ファイルとパターンファイルは、空行の位置も含めて行をそろえること。

----------------------------------------------------------------
5. 回路ファイル(.v)について
----------------------------------------------------------------
  ・用意してある回路で使われているゲート:
      INV, AND2〜4, NAND2〜4, OR2〜4, NOR2〜4
    出力ピンは Z、入力ピンは A, B, C, D。
    （プログラムは BUF, XOR, XNOR も扱えるが、用意した回路には無い）
  ・新しい回路を使うときは、circuit\ の回路と同じ形式（組合せ回路、上のゲート名とピン名）で書く。

----------------------------------------------------------------
6. tp フォルダの、実行に使わないファイル
----------------------------------------------------------------
  これらはテスト生成プログラム MTTG の出力で、SB-XID は読まない。
    pin_<回路>_C.txt      外部入力名の一覧（パターンの文字の順番。3. を参照）
    <回路>_C_DT.txt       検出できた故障の一覧（Detected）
    <回路>_C_UD.txt       検出できない故障の一覧（Undetectable）
    <回路>_C_Summary.txt  MTTG の結果の集計（パターン数・故障数・時間）
  ※ tp\1f1p\ には DT と Summary は無い（UD と pin はある）。

----------------------------------------------------------------
7. 最初の動作確認
----------------------------------------------------------------
  exe用のフォルダで、s27 を1故障だけ試すと動作を確認できる。
    1) exe用のフォルダに、次の2つのファイルを作る
         f.txt の中身: G14_G8_A sa1
         p.txt の中身: 0100001
    2) 次を実行する
         saxid_v1.exe circuit\s27_C.v f.txt p.txt r.txt x.txt --batch
    3) 次のようになれば正常
         r.txt の2行目: Case 1  G14_G8_A sa1  SAT(OPT)  Detected  3  +3 ...
         x.txt の中身 : -100--1
