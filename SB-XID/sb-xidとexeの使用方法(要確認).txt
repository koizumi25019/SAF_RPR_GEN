saxid_v1.exe 使い方
================================================================
SAT ベースのドントケア(X)判定プログラム SB-XID の実行ファイル版。
テストパターン(0/1)と、そのパターンで検出させたい縮退故障(1つ以上)を与えると、
全故障を検出したまま、できるだけ多くの外部入力を X にしたパターンを出力する。

  ・このフォルダで実行すること（clasp.exe をこのフォルダから呼ぶため）。
  ・bat はダブルクリックでよい（自動でこのフォルダに移動する）。

----------------------------------------------------------------
1. フォルダ構成
----------------------------------------------------------------
  saxid_v1.exe      本体
  clasp.exe         ソルバー（saxid_v1.exe と同じフォルダに必要）
  run_example.bat   s5378 だけを試す
  run_all.bat       通常の STTG パターン(tp\)で7回路を実行する
  run_1f1p.bat      1故障1パターン(tp_1f1p\)で7回路を実行する
  circuit\          回路  <回路>_C.v（s5378 s9234 s13207 s15850 s35932 s38417 s38584、確認用の s27）
  tp\               通常の STTG（圧縮済み。1本のパターンが複数の故障を担当）
                      <回路>_C_tp.txt        テストパターン
                      <回路>_C_tp_fault.txt  i 行目 = i 行目のパターンが担当する故障
  tp_1f1p\          1故障1パターン（1行 = 1パターン + その対象故障1つ）
                      <回路>_C_1f1p_tp.txt / <回路>_C_1f1p_fault.txt
  result\           run_all.bat / run_example.bat の出力先
  result_1f1p\      run_1f1p.bat の出力先

----------------------------------------------------------------
2. コマンドラインの使い方
----------------------------------------------------------------
  saxid_v1.exe <回路.v> <故障ファイル> <パターンファイル> <結果ファイル> <X抽出後パターン> --batch [オプション]

    <回路.v>           circuit\ の回路
    <故障ファイル>     i 行目 = i 行目のパターンで検出させる故障。複数は ; 区切り
                       1つの故障は「名前 sa0」「名前 sa1」（「名前,0」も可）
    <パターンファイル> 1行1パターン（0/1）。故障ファイルと行数をそろえる
    <結果ファイル>     出力：1ケース1行の結果（タブ区切り、下の「結果ファイルの列」）
    <X抽出後パターン>  出力：1行1パターン。X は - で表す

  オプション（どの位置に書いてもよい）
    --batch          必ず付ける（付けないと起動時に 0/1 の入力を待つ）
    --threads=N      clasp のスレッド数 1〜64（既定 1）。大きいほど速い（このPCは 16 程度まで有効）。
                     2 以上だと、同じ X 数の解のうちどれが選ばれるかが実行ごとに変わることがある
                     （X の数は同じで、ケアビットの位置だけが変わる）。1 なら毎回同じ結果。
    --max-faults=N   1行あたりの故障数の上限（既定 64）。超える行は処理せず ERROR(TooManyFaults:件数)
    --no-result      結果ファイルを出さない（X抽出後パターンだけ出す）。
                     引数は5つのままでよい（4つ目の結果ファイル名は使われない）。
                     <結果ファイル> を省いて4つにしてもよい。
    --no-debug       画面（ログ）への進捗表示を出さない
    --keep-opb       各ケースで clasp に渡した問題(OPB)を OPB_Files\ に残す（既定は削除）
    --varmap         残す OPB に変数番号と信号線名の対応表を付ける（--keep-opb と一緒に使う）
    --interactive    対話モード（故障を1つずつキーボードで入力する。--batch の代わり）

//v1 の追加オプション
    -pin <pinファイル>
                     パターンの文字の並び順を pinファイルで指定する（ハイフン1つ。後ろに空白とファイル名）。
                     pinファイルは外部入力名を1行に1つ、パターンの1文字目から順に並べたもの
                     （PBO_MTTG が出力する pin_<回路>_C.txt と同じ形式）。
                     X抽出後パターンも同じ順で出力する。対話モードでは、入力するパターンと
                     表示される X抽出後パターンが pinファイルの順になる。
                     省略時は、パターンの文字の順 = 回路ファイルの input 宣言の順。
                     pinファイルより短いパターンは、足りない入力を X として扱う。
                     次のときはエラーを表示して終了する（終了コード -1）:
                       ・pinファイルの名前が回路の外部入力に無い
                       ・同じ名前が重複している
                       ・名前の数が外部入力の数と一致しない
                       ・pinファイルが開けない / -pin の後にファイル名が無い
                     例: saxid_v1.exe circuit\s5378_C.v tp\s5378_C_tp_fault.txt tp\s5378_C_tp.txt result\s5378_result.txt result\s5378_xtp.txt --batch -pin tp\pin_s5378_C.txt

  結果ファイルの列
    Case      Case N
    Fault     対象故障「名前 sa0;名前 sa1;...」
    Result    SAT(OPT)                最適解が得られた
              SAT(FEASIBLE)           解は得られたが最適性は未証明
              UNSAT                   解なし
              ERROR(FaultNotDetected) 元のパターンで検出されない故障が含まれていた
              ERROR(TooManyFaults:N)  故障数が --max-faults を超えた
              ERROR(NoNet:名前)       回路に無い信号線名
              ERROR(Parse)            故障の行が読めない
              ERROR(OpbWrite)         OPB ファイルが書けない
              ERROR(Clasp)            clasp が結果を返さなかった（一時的な失敗のことがあるので、その行だけ再実行してみる）
    Verify    Detected（X抽出後のパターンで全故障を検出できた）/ NOT-Detected / N/A（解なし・エラー）
    Xcount    X抽出後パターンの X の数
    Diff      Xcount − 入力パターンの X の数
    Time_ms   1ケースの処理時間(ms)
    Clasp_ms  そのうち clasp の時間(ms)
    Vars/Cons OPB の変数の数 / 制約の数
  ※ X の数を集計するときは、Result が SAT(OPT) で Verify が Detected の行だけを使う。
  ※ 解なし・エラーの行は、X抽出後パターンに入力パターンがそのまま出力される。


----------------------------------------------------------------
3. コマンドラインの例
----------------------------------------------------------------
  （コマンドプロンプトで）
    cd /d C:\Users\owner\source\repos\hosonas\saxid_v1

  通常の STTG パターン
    saxid_v1.exe circuit\s5378_C.v tp\s5378_C_tp_fault.txt tp\s5378_C_tp.txt result\s5378_result.txt result\s5378_xtp.txt --batch --threads=16

  1故障1パターン
    saxid_v1.exe circuit\s5378_C.v tp_1f1p\s5378_C_1f1p_fault.txt tp_1f1p\s5378_C_1f1p_tp.txt result_1f1p\s5378_result.txt result_1f1p\s5378_xtp.txt --batch --threads=16

  結果ファイルを出さない（どちらの書き方でもよい）
    saxid_v1.exe circuit\s5378_C.v tp\s5378_C_tp_fault.txt tp\s5378_C_tp.txt result\s5378_result.txt result\s5378_xtp.txt --batch --threads=16 --no-result
    saxid_v1.exe circuit\s5378_C.v tp\s5378_C_tp_fault.txt tp\s5378_C_tp.txt result\s5378_xtp.txt --batch --threads=16 --no-result

  65故障以上の行も処理する
    saxid_v1.exe circuit\s5378_C.v tp\s5378_C_tp_fault.txt tp\s5378_C_tp.txt result\s5378_result.txt result\s5378_xtp.txt --batch --threads=16 --max-faults=128

  毎回同じ結果にする（1スレッド。遅い）
    saxid_v1.exe circuit\s5378_C.v tp\s5378_C_tp_fault.txt tp\s5378_C_tp.txt result\s5378_result.txt result\s5378_xtp.txt --batch

  対話モード（s27 で故障を1つ試す）
    saxid_v1.exe circuit\s27_C.v --interactive
      テストパターン: 0100001
      故障箇所: G14_G8_A
      故障種類(0/1): 1
      結果テキスト出力: s27_out.txt
      OPB出力ファイル: s27_case.opb
    → X抽出後パターン: -100--1 / 検証結果: Detected

----------------------------------------------------------------
4. bat ファイル
----------------------------------------------------------------
 (1) run_example.bat
     s5378 の通常 STTG パターンを1回だけ実行する（オプションは --batch のみ = 1スレッド）。
     出力: result\s5378_result.txt, result\s5378_xtp.txt

 (2) run_all.bat
     通常の STTG パターン(tp\)で、対象の回路を順に実行する。
     出力: result\<回路>_result.txt, result\<回路>_xtp.txt, result\log_<回路>.txt（画面表示の記録）
     ダブルクリック → LIST の回路をすべて実行
     コマンドプロンプトから「run_all.bat s5378 s9234」→ 指定した回路だけ実行

 (3) run_1f1p.bat
     1故障1パターン(tp_1f1p\)で、対象の回路を順に実行する。
     出力: result_1f1p\<回路>_result.txt, _xtp.txt, log_<回路>.txt
     使い方は run_all.bat と同じ。tp_1f1p\ に入力が無い回路は skip と表示して飛ばす。
     ケース数が多い（s5378: 4,511 〜 s35932: 34,534）。--threads=16 で7回路合計 約2時間。

  ※ 実行中の画面には回路ごとの開始・終了時刻だけが出る。詳しい進捗は log_<回路>.txt を見る。
  ※ 同じ出力先に書くので、bat を2つ同時に実行しないこと（clasp_out.txt も共有している）。

----------------------------------------------------------------
5. bat の書き換える箇所
----------------------------------------------------------------
  bat はメモ帳などで開いて書き換える。行頭の「rem 」はコメント（実行されない）の印。

 (1) オプション：「set OPT=」の行（run_all.bat / run_1f1p.bat）
       set OPT=--batch --threads=16              ← 今使われている行
       rem set OPT=--batch --threads=1           ← 例（rem が付いているので使われない）
       rem set OPT=--batch --threads=16 --no-result
       ...
     切り替え方：今の行の先頭に「rem 」を付け、使いたい行の先頭の「rem 」を消す。
     rem の付いていない「set OPT=」が複数あると、最後の行が使われる。
     --batch は必ず残すこと。

 (2) 対象の回路：「set LIST=」の行（run_all.bat / run_1f1p.bat）
       set LIST=s5378 s9234 s13207 s15850 s35932 s38417 s38584
     回路名を空白区切りで並べる（_C.v は付けない）。一部だけ実行したいときは減らす。
       例: set LIST=s35932 s38584
     ※ 2026-10-09 時点で run_1f1p.bat は「set LIST=s35932 s38584」になっている
       （全回路の行は rem で残してある）。全回路に戻すときは rem を付け替える。
     bat を引数付きで実行したとき（run_all.bat s5378 など）は LIST より引数が優先される。

 (3) 入力・出力のファイル名：for の中の saxid_v1.exe の行
       saxid_v1.exe circuit\%%c_C.v tp\%%c_C_tp_fault.txt tp\%%c_C_tp.txt result\%%c_result.txt result\%%c_xtp.txt %OPT% > result\log_%%c.txt 2>&1
     %%c に回路名（s5378 など）が入る。別のパターン集合を使うときや、出力先を変えるときはここを書き換える。
       例: 出力を result_test\ にする → result\ を4か所とも result_test\ にし、
           上の方の「if not exist result mkdir result」も result_test に変える。

 (4) run_example.bat
     saxid_v1.exe の行を直接書き換える（回路名・オプションなど）。
       例: 16スレッドにする → 行末の --batch を --batch --threads=16 にする。

----------------------------------------------------------------
6. 注意
----------------------------------------------------------------
 ・1行の故障数の既定の上限は 64。tp\ の通常 STTG には 64 を超える行があり、既定では
   ERROR(TooManyFaults) になる（s5378: 12行 〜 s38584: 53行）。
   上限を上げるとメモリと時間が大きく増える。
 ・--no-result と --no-debug を一緒に使うと、X抽出後パターンの検証をしないので、
   NOT-Detected やエラーの行があっても分からない。比較用のデータは結果ファイルありで作ること。
 ・ERROR(Clasp) の行は、clasp が一時的に失敗したことがある（ウイルス対策ソフトのファイル検査など）。
   その行だけ再実行すると解けることが多い。
