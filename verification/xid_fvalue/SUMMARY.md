# 故障値考慮XID(現行 InlineXID) vs 旧・外部実行体XID の単体効果 — s5378 / s9234

実行日: 2026-06-10 / ブランチ: experiment/maxdc-headroom
方法: 現行fdpの**X判定だけ**を差し替え（env `XID_EXTERNAL=<bin>` で旧外部XID(Miyase2004)を呼ぶフック）。
モデル/ソルバ/回路/limit(30)/ブロッキング帰還は完全固定 → **X判定の単体効果のみ**を分離。
データ: `results/{s5378_C,s9234_C}_{inline,external}.*` / 旧XID実体: `FaultSim/FaultSim/Build/Release/my_app`

## TL;DR（s5378・s9234 共通の傾向）
1. **X率はほぼ同等**（差は±1pt未満）。故障値考慮化は「X判定の量」を大きく変えていない。
   s5378: inline 95.06% / external 95.21%（inline −0.15pt）。s9234: inline 93.37% / external 92.44%（inline +0.93pt）。**符号も不安定＝差は小さい**。
2. **cube総数も僅差**（inline が +3.8〜4.3% 多い）。列挙故障数は両者**完全同一**（不変＝想定通り）。
3. **インライン化で約10倍高速**（s5378 ×10.4 / s9234 ×9.4）。外部プロセス起動＋回路再読込のI/O除去。これがインライン化の主目的的メリット。
4. **健全性: 故障値考慮版(inline)の方が過大評価する故障が多い** ← 最重要・両回路で一貫。complete=1 同士で fdp がズレ、**ズレの大半で inline が過大**（s5378: 33/34、s9234: 54/61）。独立シミュレーション(真値)で確認 → inline が真値より高い＝過剰展開。「XIDはfdpに影響しない」前提が破れている直接証拠。

## 健全性（最重要）

complete=1（UNSATまで完全列挙）同士なら、X判定が健全(各cube⊆検出集合)であれば**和集合=厳密なT(f)**となり fdp は一致するはず。にもかかわらずズレが生じ、**過大方向はほぼ常に inline**:

| 回路 | 両complete=1 | fdp不一致 | inline過大 | external過大 |
|---|---:|---:|---:|---:|
| s5378 | 1,457 | 34 | **33** | 1 |
| s9234 | 2,881 | 61 | **54** | 7 |

- 真値突合せ（`MDC_MC`=FdpBySim, s5378の1件）:
  `n1006gat_n1175gat_B/sa0` → **真値 0.02229**（detSolver 0.02302）。inline **0.02686=過大**、external **0.02295=ほぼ真値**。
- ∴ fdpが大きい方が「キューブに非検出ミンタームを含む過大評価」。**故障値考慮版(inline)の方が過剰展開な故障が多い**（旧XIDの方がこれら故障では健全）。前回の baseline 過大評価(s298 G14)と整合。

> 注: limit30 のため列挙故障の約半数〜2/3が打切り。打切り故障のfdp差は「別解」も含むため、健全性判断は complete=1 のみで実施。

## 解釈・原因
- **X率/ cube数の差は小さい**（s5378では0.15pt）。故障値考慮化は「X判定の量」を大きく変えてはいない。
- **大きな違いは2点**: (a) インライン化による**10倍高速化**（外部プロセス方式のI/O撤廃）、(b) **健全性の劣化方向のズレ**（inlineが33/34で過大）。
- (b)は「XIDはcube_cntのみ・fdp不変」という設計前提の破れ。故障値考慮の逆含意/補正(`f3v!=X && n3v==X`)が、検出に必要なビットまでXにしている故障がある可能性（★要コード精査）。

## 改善案
1. **最優先: 過大評価34故障の特定と原因**。`MDC_MC` を34件に回し、inlineが過大な故障で `InlineXID` のX判定が非検出点を含む箇所を特定。
2. 旧XID(external)は速度で論外（10倍遅）だが**健全性は参照**になる。inlineのX判定をexternal一致まで締める（検出CNF Fに対するany-PO最小化）。
3. インライン化自体は維持（速度の利得は確実）。
