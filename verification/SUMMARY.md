# 案1(MAXDC)/案2(MAXHAM) 組み合わせ実験 サマリー

実行日: 2026-06-09〜10 / ブランチ: experiment/maxdc-headroom
データ: `verification/results/<回路>/<構成>.{fdp.csv,log,runinfo}` / 集計: `verification/summary.csv`
再現: `verification/run_matrix.sh`（ドライバ） + `verification/summarize.py`（集計）

## TL;DR（結論）

1. **最重要 — FDP健全性の破綻**: 中規模(逐次)回路では、**無制限列挙で complete=1 にもかかわらず baseline・maxdc・maxham の FDP が食い違い、独立シミュレーションとも一致しない**。パイプライン自体（baseline 含む）に健全性バグがある。**FDPが一致しない限り、キューブ数の比較は無意味**（違う＝誤った答え同士を比べることになる）。
2. **maxham(案2) は却下**: 実行時間が **8〜15倍** に増え、かつ **FDPを過大評価**（不健全）。キューブ削減もほぼ無し〜悪化。
3. **maxdc(案1) は有望だが要改善**: キューブを **30〜75%削減**、しかも故障によっては **FDPを真値に近づける**（baselineの過大評価を是正, 例: s298 G14）。ただし (a) per-bit SAT のため**総時間はむしろ増**、(b) 一部故障で依然FDPがズレる。
4. **両立(maxdc+maxham) ≈ maxdc単体**: 案2の上乗せ価値は無く、時間コストだけ増える。

## 発見1: FDP健全性（最重要）

`MDC_MC` で **独立シミュレーション(FdpBySim, SAT不使用)** と **検出SAT-MC(detSolver)** を真値の参照として取得（生データ: `ground_truth_mc.txt`）。detSolver と sim は常に一致し、これが真値。

| 故障 | 真値(sim) | detSolver | baseline | maxdc | maxham | 外れているのは |
|---|---|---|---|---|---|---|
| s298 G14/sa0 | 0.3660 | 0.3651 | **0.3737**(+0.008) | 0.3657✔ | – | **baseline が過大** |
| s641 G120/sa1 | 0.3348 | 0.3370 | 0.3339✔ | – | **0.3496**(+0.015) | **maxham が過大** |

- **失敗モードは「過大評価」**: 最終FDP(=BDDに渡すキューブ和集合)が真の検出集合より広い ＝ **キューブが非検出ミンタームを含む**。
- **誰が外れるかは故障依存**。baseline すら常に正しくない（G14で過大）。maxdc はG14で baseline を是正する一方、s510では45故障でズレる。
- ズレ(0.008〜0.015)は MCサンプリング誤差(±0.001)を大きく超える＝**実在のバグ**。
- 小回路では全手法 fdpΔ=0。**健全性破綻は中規模(逐次)回路から顕在化**。

→ **含意: キューブ数や時間の比較は「FDPが一致する範囲」でしか信頼できない。** 中規模での maxdc の「削減」は、一部それが過小/過大の別解を出しているために生じている可能性があり、額面通りには受け取れない。

## 発見2: キューブ削減（FDPが一致する範囲で）

- **maxdc: 強力**（典型 30〜57%、s208 で75%）。
- **maxham: 弱い/不安定**（−7%〜+10%、s27/s641/s713 では**増加=悪化**）。
- **両立 ≈ maxdc**（s208 だけ 84% と突出。comboが効く稀な例）。
- `n_enum` は全構成で一定 → 削減は **「1故障あたりの本数」のみ**（等価故障数は手法不変、想定通り）。

## 発見3: 実行時間

- **maxdc は総時間がむしろ増**（s5378: 58→136s, **+135%**）。`overhead`列（`MDC_Expand` の per-bit SAT）が支配（s5378で**100s**）。testgen(SAT) 自体は本数減で減るが、展開コストが上回る。
- **maxham は激増**（s641: 5→**73s** ×15, s713: 6→47s ×8）。K→2 の幾何降下分の反復solve＋Sinz at-most 制約のCNF肥大が原因。**しかも削減せず**。最悪の費用対効果。
- **combo は maxham の時間コストを足すだけ**。

## 原因の特定

| 事象 | 推定原因（★=要確認の仮説） |
|---|---|
| maxham 過大評価(不健全) | ★多様化制約下で生成された解を XID がキューブ化する際、**検出を保証しない点が混入**。act-ガードは完全性は守るが、得られたキューブの健全性は別問題の可能性 |
| maxham 低速 | 各solveで K,K/2,…,2 の追加solve ＋ at-most(Sinz逐次カウンタ)で節が肥大 |
| maxdc 低速 | `MDC_Expand` が**ビット毎にSATを呼ぶ**（per-bit greedy）。素項化の代償 |
| maxdc 残存不健全(s510で45) | 素項展開のオラクル判定 or revert に穴。ただし故障により baseline を是正もする（効果は故障依存） |
| baseline 過大評価(G14) | ★XIDのドントケア化が一部で**過剰展開**し非検出点を含む（前回議論の「単一PO XID/PO選択」と整合的な可能性） |

## 改善案（優先順）

1. **最優先: FDP健全性の確立**。`FdpBySim`/`detSolver` を回帰に組み込み、**baseline を含め**どの故障でBDD-FDPが真値からズレるか全数洗い出す。これが解決するまでキューブ最適化の比較は土台が無い。
2. **maxham(案2) は却下**。時間・健全性とも不利。多様化路線を続けるなら**非検出点混入の修正が先**。
3. **maxdc(案1) 路線は維持しつつ2点改善**:
   - (a) **per-bit SAT をやめ、論文(All-SAT/Minimal Blocking)の unate-covering で SOUND な素項を安く出す**。`qi ⇒ F` が構成的に保証され、速度と健全性を同時に得られる。
   - (b) 逐次回路での**オラクル構築・DFF(PPI)扱い**を検証（中規模で不健全化する点と関係の可能性）。
4. **XIDの過剰展開**（baseline過大の根）を、検出CNF **F に対する最小化(any-PO)** で締め直す ← 前回までの議論の本筋。これは 3(a) と同じ方向に収束する。
