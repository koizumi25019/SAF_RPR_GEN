# PCOUNT: PODEM型入力空間探索＋メモ化による厳密数え上げ

**v2 追記（2026-07-13）: 文献準拠版に全面改訂。以下の v1 記述の後に v2 の節あり。**


実施日: 2026-07-09 / ブランチ: verification
関連: [[cube-explosion-research-state]] [[bdd-exact-fallback]]
前段: `verification/split/SUMMARY.md`（SPLIT 却下と「原理的限界」の分析）

## 位置づけ

incomplete 根絶の第4案。制約（CaDiCaL 改造なし・外部モデルカウンタなし・回路構造からの
BDD 直接合成＝従来手法なし）をすべて満たす**自作の厳密数え上げ**:

- 探索は **ATPG(PODEM) 流のトップダウン PI 割り当て**。SATソルバも BDD 合成も使わない。
- 打ち切り故障に対し、関連領域（TFO PO 群の fanin コーン）のサポート PI へ 0/1 を
  順に割り当て、**3値故障シミュレーション**で「全拡張が検出/非検出」を早期確定して数える。
- **影響キー・メモ化**が核: 「未確定 PO にまだ影響し得るネット」だけの3値状態をキーに
  等価部分問題を共有する（値が確定したゲートは定数として振る舞うため、その上流の
  割り当て差はキーから消える＝ OBDD のノード等価と同じ発想）。全域状態キーでは
  ヒット 0 だったものが、影響キーで最難故障に 7.8万ヒット。
- サポート PI の割り当て順は故障サイト→TFO PO の fanin DFS 順（構造的局所性で
  関連 PI をクラスタ化する古典的 BDD 順序ヒューリスティック）。
- 深さ ≤ サポート数で必ず停止。`PCOUNT_MAXNODES` 超過時のみ諦めて従来の capped。

`src/fdp/pcount.c`（env `PCOUNT=1` / `PCOUNT_MAXNODES` 既定200万 / `PCOUNT_CACHE` 既定2^20）。
メモ化キーは 128bit ハッシュのみ保存（衝突確率 ~2^-128 を実用上無視する割り切り。厳密性の
建前では全キー保存が正道）。

## 結果

- **c17a（-limit 2 で12故障を強制打ち切り）**: 全故障厳密化・fdp ゴールデン完全一致・incomplete 0。
- **s5378 最難故障 n673gat/sa0（det_paths=620億、従来 limit=50000 でも真値の90%止まり）**:
  **1.61s / 157,003 ノード / cache_hits 77,924 で厳密 fdp=6.8008024013e-02**。
  BDD_EXACT（従来手法の参照値）と完全一致。← 「原理的限界」とした故障が解けた。
  ただしこれは「キューブでの完全被覆」ではなく「厳密な数え上げ」による完全化
  （キューブは -limit ぶんの部分集合のまま。complete=1 の意味は「fdp が厳密」）。
- **s5378_l30 全体（GT_BDD 併用の先頭769行）**: incomplete 28 ≒ baseline 同区間の**約87%を解決**、
  GT 照合で UNSOUND 0。
- **s5378_l30 全体（GTなし・MAXNODES=40万、1200s 時点 4647行）**: incomplete 130 ≒ **約90%解決**。
  ただし完走には ~2700s 見込みで、baseline 57s に対しまだ重い。

## ボトルネック（次の作業、未実施）

1. **全再シミュレーション**が律速（1ノードあたり関連領域 ~2.6k ゲートを毎回評価、~5万ノード/s）。
   イベント駆動の差分シミュレーション＋undo ログで数倍〜10倍の余地。
2. 影響マーキング＋ハッシュも O(領域)/ノード。差分化はやや複雑。
3. bail する故障（400k ノード超）が1件 ~8s を浪費。適応的キャップ（1st pass 小さく、
   残りだけ大キャップ+大キャッシュで再挑戦）が有効なはず。
4. 変数順はまだ素朴。cache_hits を最大化する順序（reconvergence 考慮）で改善余地。

## 暫定結論

「キューブ被覆が指数の故障は完全化不可能」という前回の限界分析は、**「キューブで被覆する」
ことに固執した場合の話**だった。数え上げ（fdp の厳密化）が目的なら、PODEM 探索＋影響キー・
メモ化で**最難クラスの故障が秒オーダーで厳密化できる**ことを実証した。工学的高速化
（差分シミュレーション）を残すが、incomplete 根絶の本命ルートとして成立している。

## 出典と対応

| 部品 | 出典 | v2 での実装 |
|---|---|---|
| 双対early termination | Möhle & Biere, *Dualizing Projected Model Counting*, ICTAI 2018 (DUALIZA) | 3値simで「PO差確定→全拡張検出(2^未割当)」「全PO一致確定→非検出」。回路では P矛盾/N矛盾が出力0/1確定に相当 |
| レベル別等価キャッシュ | Huang & Darwiche, *Using DPLL for Efficient OBDD Construction*, SAT 2004 (Alg.3 separator) | 各ネットの確定深さ maxdep と最終使用深さ useu を静的前計算し、separator（maxdep≤d<useu のネット）の3値状態をキーに。健全性は「割り当ての影響は separator 経由でしか未確定領域に届かない」ことによる |
| キーの差分更新 | （Zobrist ハッシュ、標準技法） | enter/leave リストを深さ別に前計算し、遷移ごとに XOR で O(変化分) |
| 差分シミュレーション | イベント駆動（3値の単調性 X→0/1 で処理順自由・undo ログで巻き戻し） | 全再simを廃止 |
| 部分問題キャッシュの系譜 | Bayardo & Pehoushek AAAI 2000 / Thurley sharpSAT 2006 | 同族。回路では [2] の separator 方式が自然 |

v1 の「影響キー」（意味論的な到達可能性でフィルタ）はヒット率は高いが毎ノード O(領域) の
再計算が必要だった。v2 の構造的 separator キーはヒットがやや粗い代わり O(変化分) 更新。

# HALL 本家との実測比較（2026-07-13）

検出回路を AIGER 出力する `AIG_DUMP=path`（`src/fdp/aig_dump.c`、既定無効）を実装し、
同一インスタンスで HALL（SAT'23/24 公式実装、IntelSAT+CaDiCaL）と比較した。
AIG の正しさは c17a c/sa0 で確認（mars-dis の disjoint 被覆 9 モデル = fdp 0.28125×2^5 に一致）。

## 故障単位の比較（s5378_C、厳密 fdp は BDD_EXACT 参照値）

| 故障 | 厳密fdp | HALL tale | HALL roc | 我々の列挙(XID+MAXDC_CORE,無制限) | 我々のPCOUNT |

## 知見

1. **我々の列挙器は HALL と互角**。モンスター n673gat も非disjointなら 7万本規模で
   完走可能で、我々も 74,056 本/49.6s で完走・fdp 厳密一致（従来「完全列挙が終わらない」と
   していたのは limit=50000 までしか試していなかったため）。ROC との同型性が実測でも裏付け。
2. **列挙の難しさ（カバーサイズ）と数え上げの難しさ（separator 幅・3値simの悲観性）は別軸**。
   n1080/n1148 は D_f≒単一リテラル（列挙は自明）なのに PCOUNT は 3値シミュレーションの
   悲観性（意味的に確定でも sim では X）で 1億ノード焼く。逆に n673 は列挙 50s/数え上げ 0.35s。
3. スタック評価（s5378 全4551故障）: baseline(l30) incomplete 2,980 →
   `MAXDC_CORE+PCOUNT`(l30) **245** (253s) → 同(l300) **186** (542s)。
   残りは両軸とも難しい真の難故障。
4. 次の一手: (a) PCOUNT の早期終了の意味論化（3値simの悲観性解消。HALL 論文の
   satisfying→entailing の教訓のカウント版）、(b) カット幅最小化の変数順、
   (c) エスカレーション運用（limit→MAXDC→PCOUNT→無制限列挙の順に安い手から）。
