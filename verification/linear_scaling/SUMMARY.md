# 全故障 FDP に向けた列挙・ドントケア判定・故障間再利用の改善

実施日: 2026-09-11。独立試作であり、本体の `src/` は変更していない。
ソース・入力・結果・検証ログはこのディレクトリ以下に置く。

前回の [可逆線形変換](../linear_coordinates/SUMMARY.md) を出発点に、
**SAT で検出入力を生成し、非検出 SAT オラクルで領域を広げ、生成領域の和集合だけを BDD で数える**。
PCOUNT、外部モデルカウンタ、回路からの検出関数 BDD 構築は解法に使用していない。

## 結果

全故障については「一故障の最高速度」よりも、次の組合せが有効だった。

1. 回路の前処理を共有し、故障ごとに再構築する論理を故障コーンに限定する。
2. 非検出となる入力をビット並列シミュレーションで見つけ、必須リテラルの SAT 再判定を省く。
3. 入力の置換・反転で同じ検出関数になる故障について、厳密値と被覆を参照して再利用する。
4. 通常のキューブで遅い故障には、複数ビットの許容状態集合を持つ領域を使う。

| s641: C++・線形座標、各故障を個別列挙 | 1,274 | 1,274 | 1,274 | 13.451 s |
| s641: 上記＋故障間再利用 | 1,274 | 391 | 1,274 | 4.758 s |
| s641: 上記＋必須リテラルのシミュレーション判定 | 1,274 | 391 | 1,274 | **3.843 s** |
| s5378: C++・線形座標・再利用 | 4,551 | 3,848 | 4,545 | 237.653 s |

途中で消費した計算も計上している。第一段階だけの打ち切り値を厳密値とは扱っていない。
幅 3 を先に使う構成では、未完了の `n740gat/sa0` を通常キューブで再試行し、
150.400＋1.664＝152.063 秒で全完了した。二つの構成で全 4,551 故障の有理数が一致した。

s641 の 1,274 故障は既存 CSV の対象欄から抽出した評価集合で、現行本体の構造等価代表
463 故障とその等価出力を合わせた全 1,274 故障に相当する。
s5378 は 4,551 代表故障。対象リストを `cases/s641.faults`, `cases/s5378.faults` に固定した。

**13.451→3.843 秒は同じ独立試作内の比較であり、本体比 3.5 倍を意味しない。**
現行本体は s641 で GT 検証込み約 3.716 秒だった。
簡単な故障が多い回路では Python の制御・プロセス起動・ファイル I/O が試作の下限になっている。

完全化した本手法との同一条件の速度比較にはならない。

環境は Intel Core i7-13700K / Linux (WSL2)、同梱 CaDiCaL・CUDD・GMP。
列挙器は一スレッド。探索的な単回測定で、CPU 固定や統計的な反復測定は行っていない。
少量の独立検証が並行した区間もある。十万故障級での時間・メモリ性能は未検証。

## 必須リテラルの証拠を使い、SAT 判定を省く

検出モデルを `m`、検出関数を `D` とする。入力 `i` だけを反転した `m'` が
`D(m')=0` なら、`m` を含む健全なキューブから `i` の固定は除去できない。
`m'` がその除去の反例になるためである。

この「残すべき固定」を最大 64 個ずつビット並列シミュレーションで調べる。
UNSAT コア取得後、必須と分かったリテラルには削除試行の SAT を呼ばない。
**反転後も検出できることだけから DC とは判断しない。実際の固定除去は必ず
`非検出 CNF ∧ 残す固定` の UNSAT で証明する。**
従って一ビットずつは反転できても同時に反転すると非検出になるケースを誤って広げない。

| 条件 | シミュレーションなし SAT 呼出し | あり SAT 呼出し | 列挙時間なし→あり |
|---|---:|---:|---:|
| s641: 再利用後の 391 関数 | 213,501 | 55,843 | 1.658→0.810 s |
| s5378: 再利用後の 3,848 関数 | 11,333,782 | 4,866,159 | 183.236→105.848 s |

s5378 の比較は双方 2 秒上限があり、完了数は同一ではない。
SAT 呼出しを省くと学習・解順序も変わるため、生成キューブ数まで同一になるとは限らない。
両条件とも完全だった 4,545 故障では、FDP の厳密有理数が全て一致した。

実装: `native/enumerator.cc` の `Sensitivity`、`experiment.py` の `--simulate`。

## 0/1/X を、複数ビットの許容値集合に広げる

互いに重ならない座標ブロック `B_j` を作り、一つの生成領域を

`R(y) = AND_j [ y_(B_j) ∈ S_j ]`

と表す。例えば二ビットで `{01,10,11}` を許す領域は一つの通常キューブでは表せないが、
一つのブロック条件なら表せる。これは前回の XOR 座標変換とは別の圧縮能力である。

各状態に `q_(j,v) ⇔ (y_(B_j)=v)` という CNF を作る。SAT モデル以外の状態を禁止する
`¬q_(j,v)` を assumptions とし、非検出オラクルの UNSAT コアと固定除去で禁止状態を減らす。
得られた領域の禁止節は、残った `¬q` を全て反転した **一つの OR 節**。
領域ごとの新しい変数は不要で、重なりも許す。

必須状態もシミュレーションで判定できる。あるブロックだけを状態 `v` にした入力が非検出なら、
その `v` の禁止は除去できない。その他の禁止除去は全て SAT が保証する。

BDD に渡すのは SAT が生成した `S_j` のリストだけである。
`region_union.cc` は回路を読み込まず、各許容状態集合の BDD を作り、積と和で重複を処理する。
局所ブロック幅は最大 6、状態数は最大 64 に制限する。

| 故障・条件 | 通常キューブ | 幅 3 の領域 | 列挙時間 | 和集合処理込みの故障処理時間 |
|---|---:|---:|---:|---:|
| s5378 `n1592gat/sa0` | 12,788 | 899 | 1.980→**0.228 s** | 2.172→**0.277 s** |
| s5378 `n291gat/sa1` | 5,383 | 1,557 | 1.996→**0.918 s** | 5.021→**1.105 s** |

各行の両側は C++・線形座標・シミュレーション判定を使用し、4 秒上限で完了した測定。
FDP はそれぞれ `48825/4194304`, `4005879917/8589934592` で厳密一致。
元回路の独立 CNF による全領域の健全性・完全性も確認した。

表現上の効果を分離するため `cases/orpairs12.v` を追加した。
`D = AND_(i=1..12) (a_i OR b_i)` の出力 sa0 は、通常キューブで **4,096 本**、
二ビットの状態集合では **1 領域**で完全列挙できた。SAT 呼出しは 15,098→3、
列挙は 0.254→0.000777 秒、全処理は 0.284→0.00612 秒。
両方の FDP は `(3/4)^12 = 531441/16777216`。
これは人工回路での表現力の確認であり、実回路全体に同じ倍率が出ることを意味しない。

## 故障間の再利用と前処理

各故障の検出式 DAG を、最初に現れた入力の順序・位相で符号化する。
ノード種別・全ての子・否定辺・再共有関係まで含む**符号列全体の一致**を確認する。
ハッシュ値のみで等価と判断しない。これにより

`D_g(y) = D_f(P y XOR b)`

という入力全単射が得られ、均等独立入力での FDP は等しい。
異なる故障の元の入力空間でテスト集合が同一である必要はない。
被覆を取り出すときは、代表のリテラルをこの置換・反転で写す。
前段の `y=A_f x` も正則なので、全体の写像も全単射である。

本試作では FDP と代表被覆への参照を保存し、全対象への被覆の複製はしない。
`verify.py --reused` は実際にリテラルを写して元回路の CNF で確認する。
この照合は十分条件であり、完全な NP/NPN 正規化ではない。
可換演算の並びなどが違う同値関数は見逃し得る。出力反転による再利用も行っていない。

`basis/basis.py` は前処理を回路単位で共有し、最大 128 単項式までの ANF と
最大 6 入力の局所真理値表で affine 部分式を認識する。
制限を超える場合は元の論理を保持し、近似しない。
長い XOR を優先して基底に取り込み、正則行列に補完する。
故障の届く出力とそのコーンだけを再構築し、健全側の式を共有する。

## 前回との比較と不採用条件

元の `n673gat/sa0` 単独ケースでは以下になった。

| 条件 | キューブ／領域数 | 列挙時間 |
|---|---:|---:|
| 前回: Python・旧 XOR 基底 | 1,462 | 2.212 s |
| C++・旧 CNF・greedy | 1,462 | 0.424 s |
| C++・長い XOR を優先した基底 | 947 | 0.281 s |
| 上記＋必須リテラルシミュレーション | 987 | **0.156 s** |
| 上記を幅 6 の領域で列挙 | 626 | 0.295 s |

FDP は全て `292092239/4294967296`。
最後の二条件は元回路 CNF でも全被覆を独立検証した。
前回比の大きな改善にはプロセス間通信の除去も含まれる。
領域数が少なくても SAT 判定・エンコーディングが重ければ時間は悪化する。
このため幅の大きいブロックを一律に使うことは現時点では推奨しない。
ただし s5378 全体では幅 3 を主に使う方が速く、上表のとおり通常キューブへの再試行と
組み合わせて 152.063 秒になった。入力に対する最適な幅の選択は未解決。

旧 CNF で core のみは 12,540 本・1.836 秒、QuickXplain は 1,546 本・0.723 秒となり、
greedy の 1,462 本・0.424 秒に劣った。短い基底優先も長い基底優先より遅かった。

## 検証と既存出力の注意点

- c17a の代表 22 故障 × 幅 1/3/6 = 66 実行で、全 32 入力のシミュレーション、
  元回路 CNF による健全性・完全性、和集合 BDD、ゴールデンが全て一致。
- s641 の全 1,274 故障で、再利用なし・再利用あり・シミュレーションありの厳密有理数が全て一致。
- 再利用後の被覆を実際に変換し、s641 の固定乱数サンプル 32 故障、s5378 の 24 故障を
  元回路 CNF で独立証明。難しい故障と人工回路の領域も独立証明。
- 本体を出力先だけ変更して c17a / s641 / s5378_l30 で回帰実行。
  `GT_BDD` は既存本体の回帰検証にのみ使用し、各代表故障は `ALL VERIFIED`。
  c17a はゴールデン一致。s5378 で本体が完全だった 1,571 故障は新方式とも全て一致。

比較中に、**既存本体の s641 の等価故障エコー 8 行に極性の不一致**を見つけた。
`gmp_wrapper.c` の `OutputEquivFaults` が AND/NAND を同じ `SF0` 条件、OR/NOR を
同じ `SF1` 条件で出力している。NAND 入力 sa0 は出力 sa1 に対応すべきだが、
出力 sa0 の確率をエコーしている。例: `G379_G214_A/sa0` のエコーは約 0.241691、
個別の SAT 列挙・独立 CNF 検証では `3273281/16777216`（約 0.195103）。
同じ故障を本体に明示指定して再計算すると後者に一致した。
GT は代表の被覆を検査するため、エコー行のこの不一致は検出しない。

今回 `src/` は変更していない。この既存不具合の再現値・8 故障の独立証明は
`results/measurements.json` の `s641_echo_diagnostics`、生ログは `runs/s641_recheck*` に保存した。
新方式同士の比較にはエコー値を使っていない。

## 再現

リポジトリルートから実行する。依存ライブラリは既存のビルドを使用する。
実行中に同じ出力先や実行バイナリを上書きしないこと。

```bash
bash verification/linear_scaling/build.sh

python3 verification/linear_scaling/batch.py \
  --net input/circuit/s5378_C.v \
  --faults verification/linear_scaling/cases/s5378.faults \
  --expand-branches --simulate --seconds 2 \
  --outdir verification/linear_scaling/runs/reproduce_s5378

python3 verification/linear_scaling/complete_batch.py \
  --initial verification/linear_scaling/runs/reproduce_s5378 \
  --outdir verification/linear_scaling/runs/reproduce_s5378_completed

python3 verification/linear_scaling/verify.py \
  --c17 verification/linear_scaling/runs/reproduce_c17

python3 verification/linear_scaling/verify.py \
  --reused verification/linear_scaling/runs/reproduce_s5378 --sample 24
```

単独実験は `experiment.py --net ... --fault ... --stuck 0 --simulate --width 3 --prefix ...`。
被覆の独立証明は `verify.py --net <元回路またはexpanded.v> --prefix <実験prefix>`。
batch の `--no-sharing` で故障間再利用を止め、`--simulate` の省略でシミュレーション省略を止める。
152 秒の条件は batch に `--width 3`、後段の complete_batch に `--width 1` を指定する。

保存物:

- `results/s641_exact.csv`, `results/s5378_exact.csv`: 全対象の厳密有理数と完了フラグ。
- `results/measurements.json`: 比較表の測定値・回帰結果・既存エコー不一致の診断。
- `runs/`: 故障別 CNF、生成キューブ／領域、基底、SAT 統計、BDD 和集合統計、独立証明。
  大量の中間ファイルとバイナリは `.gitignore` 対象。

SAF の組合せ化した回路で評価した独立試作。TDF、重み付き・相関のある入力分布、
十万故障級、本体の支配流用との併用は未実装・未評価。
任意の回路で完全列挙が小さくなる保証はない。

## 文献と今回の位置付け

- Richard L. Rudell, *Multiple-Valued Logic Minimization for PLA Synthesis*, UCB/ERL M86/65, 1986.
  [原報告](https://www2.eecs.berkeley.edu/Pubs/TechRpts/1986/ERL-86-65.pdf)。
  状態集合を持つ多値キューブ、入力のグループ化、EXPAND が今回の領域表現の背景。
  本試作では非検出 SAT の assumptions/core と一節のブロッキングに組み合わせた。
- Dror Fried, Alexander Nadel, Yogev Shalmon, *AllSAT for Combinational Circuits*, SAT 2023.
  [論文](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.SAT.2023.9)。
  回路情報・シミュレーションを使った小さい implicant 生成の関連研究。
  今回の一ブロック変更による「必須制約の反例証拠」は TALE/MARS の実装そのものではない。
- Xuegong Zhou, Lingli Wang, Alan Mishchenko, *Fast Adjustable NPN Classification Using Generalized Symmetries*, TRETS 12(2), 2019.
  [論文](https://people.eecs.berkeley.edu/~alanmi/publications/2019/trets19_npn.pdf)。
  入力置換・位相を考慮した関数分類と計算再利用の背景。
  今回は全 NPN 正規化を行わず、入力置換・反転で一致する DAG の十分条件だけを使う。

既知の概念を FDP の SAT 完全被覆に組み合わせた実験であり、ここで理論上の新規性を主張しない。
