# 故障値考慮XID 過大評価バグ — 根本原因・修正・検証

実行日: 2026-06-10 / ブランチ: experiment/maxdc-headroom
発端: `verification/xid_fvalue/` で判明した「故障値考慮XID(InlineXID)が多数の故障でFDPを過大評価」する健全性バグ。
参考: 発表スライド「正常値/故障値を考慮したドントケア判定」(2ルール: 伝搬経路1本選択+サイド入力を非制御値)。

## 根本原因
`src/fdp/xid/XID.c` の `Xfilling` で、**故障サイト(分岐ネット)の `fault_3value` を故障源として固定していなかった**。

- fsim は故障サイトに stuck 効果を注入する（例 sa0 → `fault_2value = 0`）。
- しかし `Xfilling` の3値再導出で、**故障サイトの駆動ゲート(ステム)からの前方含意が `fault_3value` を上書き**し、`normal_3value == fault_3value` になってD効果(0/1)が消滅する。
- D効果が消えると、故障ゲートの活性化条件（側入力 = 非制御値）が後方含意されず、必要なPIがタグ未設定のまま残る。
- `InlineXID` の最終ループ(XID.c:329)は `normal_3value` のみ読むため、その必要PIが **'X'** として出力される。
- 結果、キューブが非検出ミンタームを含み、和集合(=BDD)が過大 → **FDP過大評価**。
- XID.c:273 の fix-up は `f3v != X && n3v == X` の時しか normal を復元せず、`f3v` ごと潰れた本ケースを救えない。

## 実証（s5378 `n1006gat_n1175gat_B/sa0`）
分岐故障: ステム `n1006gat`(=INV(n630gat)) の gate2799 `NOR2(n621gat, n1006gat)→n1175gat` への分岐が sa0。

- 独立ビット並列シミュレータ(`check.py`)で 25キューブ中 **2本(cube1,9)が非健全** = ミンタームの約50%しか故障検出せず。
- 原因PIは `n622gat`(=`n621gat`、活性化に `=0` 必須だが 'X' 出力)。`pinpoint.py` で P(det|=1)=0, P(det|=0)=1 を確認。
- C側診断(`XID_DBG`)で、非健全キューブでは故障サイト自身が `f3v=1`(真値0に反し上書き)、`n622gat` は `tag=0`(未確定) を確認。
- fdp = **0.0269(過大)** vs 真値 **0.0223**(FdpBySim)、external XID 0.0229。

## 修正（1行）
`Xfilling` 冒頭（PO push 直後）に故障サイトの固定を追加:
```c
ED_push_Xpath(&nl[fsigID], xid_tag_base, var_info);  // 故障サイトを故障源として固定
```
故障サイトの3値が真の2値に固定され、以後の含意が上書きできなくなる（故障サイトの normal は活性化に常に必要なので固定して損失なし）。
