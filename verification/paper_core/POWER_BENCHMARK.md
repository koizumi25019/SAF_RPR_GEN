# 低消費電力 ON の遷移故障 CORE 実験

2026-10-06。今回は ON のみを測定し、電力制約なしの再測定はしない。
小規模は s27/s208、中規模は s5378/s9234 の DFF 入り元回路。
以前の縮退故障表の `*_C` は使用しない。c17a は DFF がないため LOC 遷移故障の対象外。

## 条件と再現

- 遷移故障 TDF / LOC、CORE、流用 off、追加検証 off。
- 正常回路の2時刻間の遷移数を元信号線数（分岐を含む）の20%以下に制限する。
- 小規模は全代表故障・無制限。ウォームアップ1回を除外し、7回測定の中央値。
- 中規模は全代表故障・limit30、ウォームアップなしの1回。
- 1実行の実時間上限は1,800秒。`--wall-limit 0` で解除できる。
- 実験は直列実行。この測定では `taskset -c 0` で単一CPUに固定。
- 任意の研究・検証環境変数はシェルが除去する。GT/core追加検証を性能時間に含めない。
- 時間は本体 C の CPU/経過時間ログ（0.001秒刻み）。
  旧小規模 SAF 表の CPU は子プロセスの user+system 全体（6桁）で、開始・終了処理を含む点が異なる。
  旧中規模表は今回の完走時と同じ本体ログ。ミリ秒単位の比較ではこの測定範囲の差を区別する。

```bash
cd /workspace/SAF_RPR_GEN_core
taskset -c 0 bash run_tdf_power_benchmark.sh
# 特定回路だけ再実行する場合
taskset -c 0 bash run_tdf_power_benchmark.sh s5378 s9234
python3 verification/paper_core/export_tdf_power.py \
  --run-dir "$(cat output/paper_core/tdf/lp20/benchmark/latest.txt)"
```

シェル→`.set`→C の既存の流れ。Python/openpyxl は終了後の集計・Excel出力だけに使う。
設定は `input/script/{s27,s208}_tdf_core_lp20.set` と
`input/script/{s5378,s9234}_tdf_core_lp20_l30.set`。
出力先を毎回新規作成し、生の故障CSV・ログ・stderr・使用`.set`・バイナリSHA256を保存する。

## 結果の読み方

`tdf_power_on_results.xlsx` はグラフなしの数値表。
実行時間、キューブ数、故障完了、X率、判定回数、時間内訳、電力条件、測定明細、故障別FDP、条件・注記の10シート。
未完走があれば `未完走実行` を追加する。timeout の時間は停止時点までの消費時間で、完走時間ではない。
timeout をキューブ0や全故障テスト不能と解釈しない。全件のX率や完了数も空欄にする。
以前の `paper_core_comparison.xlsx`（縮退故障・電力制約なし）は変更せず、並べて比較する。
故障モデル、対象故障数、閾値、limit は区別して読む。

FDP の分母は従来の全自由入力 `2^(PI+初期DFF状態)`。
`complete=0` の FDP は下界であり、厳密値ではない。
中規模の最小・最大CPU秒は1回分の同じ値を記録する。時間変動を評価した測定ではない。
キューブ0の X率・平均ケア数は未定義なので空欄にする。
core直後の X率は極小化を含む実行の途中の統計で、core単独列挙実験ではない。

小規模の各測定結果は、前の独立全列挙シミュレーションで確認済みの全故障FDPと一致。
測定反復間で故障ごとのFDP、complete、キューブ数およびcore統計が同じことも確認済み。
中規模の今回の性能測定では独立BDDや全X展開検証は実行しない。

1秒上限の別実行で timeout の記録・時間保存・未完走専用Excel出力を確認し、
s27 の別実行で完走時の時間上限つきシェル・7回集計・キューブ0処理も確認した。
これらの動作確認は性能測定値には含めない。

## 中規模

s5378 は実時間1,800.210秒で打ち切り、停止直前の `/proc` による累計 user+system は1,799.010秒。
全件集計は未取得。タイムアウト時にCSVへ書き出されていた行は0で、
バッファ中の処理済み行数や生成中のキューブ数はここから判定しない。
このケースは開始済みの実行に外部監視を追加して停止したため終了コード143。
再現シェルの GNU timeout は同じ1,800秒上限で終了コード124を記録する。

通常シェルの timeout 時の消費CPU時間は Bash `time` の待機子プロセス user+system から記録する。
これも完走時間ではなく、停止までに消費した値。

s9234 も実時間1,800.029秒でタイムアウト、停止までの累計CPUは1,798.703秒。
CSV保存済みの197代表故障は全て complete=1 / FDP=0。等価故障行を含む保存済みCSVは217行。
これは全11,328代表故障の集計ではなく、処理済みの一部に限る。
未保存・未処理の故障のFDPや生成中のキューブ数、全件のX率は未取得。
